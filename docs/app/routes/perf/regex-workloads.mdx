# Regex Benchmarks

Ferroni is compared with C Oniguruma, Ruby's Onigmo, PCRE2 (interpreter and
JIT), fancy-regex and Rust's `regex` crate on regex tasks taken from ten
open-source projects. Every engine has to reproduce each task's expected output
before it is timed. This page shows the summary; every table and the raw
measurements are [in the repository](#all-numbers-and-raw-data).

These are isolated regex steps, not the complete validators, parsers or
renderers. The 513 upstream-derived inputs define the expected output; they are
not a model of production traffic.

- **Same output first.** An engine that rejects a pattern or returns a
  different result is left out of that task instead of being timed.
- **Three phases.** Compile prepares one pattern, first use adds its first
  input, and steady reuse runs a prepared pattern over all of its inputs. The
  chart shows steady reuse.
- **Repeated on separate machines.** Three processes per platform, each on its
  own Blacksmith VM, with 30 Criterion samples per phase. A task counts for one
  engine only when all three runs agree; otherwise it is inconclusive.
- **One aggregate per pair.** The geometric mean of the median case ratios
  within each task family, then across families. Each pair covers only the
  tasks both engines can run, so rows with different task counts are not a
  ranking.
- **Standard API.** The baseline uses Ferroni's standard `Regex` methods. The
  fallible `*_with` methods currently allocate fresh match workspace per search
  and are slower on reuse; the repository tables list them as
  `rust_erroraware`.

## Syntax coverage

The performance tasks use only part of each engine's syntax. This matrix checks
selected features directly, one executable example per cell.

<RegexFeatureMatrix />

A check means the illustrated syntax returns the expected match; a cross means
it is rejected or behaves differently, though a rewritten pattern may still
solve the task. Variable-length look-behind here includes an unbounded `\s*`;
multi-character case folding means `strasse` matching `straße` with case
ignored. The checks live in
[`tests/regex_feature_matrix.rs`](https://github.com/sebastian-software/ferroni/blob/main/tests/regex_feature_matrix.rs).
