# Engine Comparison

Ferroni next to seven other engines on two cloud hosts: C Oniguruma, Ruby's
Onigmo, PCRE2 with and without JIT, fancy-regex, Rust's `regex` crate and, for
the TextMate scanner replays, Shiki's JavaScript engine. The run comes from the
manually dispatched
[Blacksmith comparison](https://github.com/sebastian-software/ferroni/actions/workflows/blacksmith-comparison.yml)
workflow, so anyone can repeat it on the same runner types.

Every engine first has to reproduce Oniguruma's matches and capture bounds for
a case, or every captured Shiki result for a scanner replay. Only then is it
timed. Where an engine rejects a pattern or answers differently, the table says
`n/a` and [the reason is listed](#cases-an-engine-cannot-run). A dash means the
engine has no variant for that case: `regex` lacks the syntax, or the case uses
an API (Oniguruma's RegSet, the grammar loader) the engine does not have.

## How to read the tables

Each cell holds the **Apple Silicon** value on top and the **x86-64** value
below it. The Ferroni column is the Criterion mean. Every other column is that
engine's time divided by Ferroni's, the same convention as "C / Ferroni" on the
other pages: **above 1.00, Ferroni is faster**; below 1.00, the other engine is.

- **Patterns and compilation** time one search or one compile call, with the
  same validated pattern and text for every engine.
- **Scanner replays** play back real TextMate scanner calls captured from
  Shiki: C++ (4,862 calls), Java (3,920) and SCSS (3,744). Ferroni and C use
  Oniguruma's RegSet scanner (C through the scanner wrapper of
  vscode-oniguruma). Onigmo, PCRE2 and fancy-regex have no RegSet and search
  pattern by pattern, which is what vscode-oniguruma itself does on lines of
  1,000 bytes or more. Shiki JS is `@shikijs/engine-javascript` 4.5.0 with its
  defaults, timed in Node over 1 ms batches rather than with Criterion.
- **Empty captures:** vscode-textmate skips zero-length captures, so a replay
  accepts an empty group reported as unset (or the reverse). Shiki JS needs
  this for 96 C++ calls and 16 Java calls; no other engine does.

These are point estimates from one run with 30 samples over 3 seconds per case
and engine. Differences within about 10% are not a ranking. The raw estimates,
confidence intervals and logs are kept with the
[run data](https://github.com/sebastian-software/ferroni/tree/main/benches/results/blacksmith-2026-10-01).

## Results

### Shared syntax

Patterns the `regex` crate also runs. No single engine wins here: PCRE2's JIT
has the fastest search in about half the cases and the `regex` crate in most of
the rest, mainly literal-led searches and validations. fancy-regex hands these
patterns to `regex` and lands close to it. Ferroni beats C Oniguruma on every
search, by 1.1x to 10x. Onigmo and the PCRE2 interpreter are mixed against
Ferroni: each is faster on some short searches and slower on others.
Compiling is cheap in both Oniguruma implementations and the PCRE2
interpreter; the JIT and the automaton-based engines pay more up front.

### Oniguruma syntax

Lookaround, backreferences, atomic and possessive groups, subexpression calls,
the absent operator `(?~...)` and conditionals. PCRE2's JIT has the fastest
search wherever it can run the pattern. Against C Oniguruma, Ferroni is ahead
by 3.0x to 3.7x on lookaround and lookbehind and within about 15% on the absent
operator, conditionals and case-insensitive backreferences, where the lead
changes between the hosts. Both Oniguruma implementations compile the lookbehind pattern 2.4x to 3.6x faster than Ferroni. fancy-regex runs every pattern
but one in its Oniguruma mode, 1.5x to 4.5x slower than Ferroni.

### TextMate scanners

The workload Ferroni was built for, with the complete Shiki grammars for
TypeScript, CSS and Rust: compiling a grammar, re-scanning one line, and
tokenizing a document line by line. Only Ferroni and C Oniguruma have a grammar
loader and RegSet scanner here. Ferroni is 3.3x to 68x faster at scanning;
grammar compilation is mixed, with C Oniguruma faster on the Rust grammar on
both hosts and on the TypeScript grammar on x86-64.

### Shiki scanner replays

Real scanner calls captured from Shiki for whole C++, Java and SCSS documents,
and for the scanner group that dominates each document. Ferroni is 2.1x to 3.1x
faster than C Oniguruma on C++, 3.4x to 4.4x on Java and 13x to 21x on SCSS,
and 1.6x to 3.6x faster than Shiki's JavaScript engine. Engines without a
RegSet fall far behind on scanner work. Only Ferroni, C Oniguruma, fancy-regex
and Shiki JS run all three grammars as they are.

## Cases an engine cannot run

| Benchmark                                 | Engines          | Reason                                                                                                              |
| ----------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| `oniguruma_features/absent_comments`      | PCRE2, PCRE2 JIT | PCRE2 has no absent operator: `unrecognized character after (? or (?-`                                              |
| `oniguruma_features/subexp_call_balanced` | fancy-regex      | Group 1 after the recursive call holds the innermost match (`17..21`); Oniguruma reports the outermost (`4..21`)    |
| `cpp_scanner/document`, `group_78`        | PCRE2, PCRE2 JIT | The C++ grammar uses Oniguruma's stacked quantifier `\s+{0,1}`: `quantifier does not follow a repeatable item`      |
| `cpp_scanner/document`, `group_78`        | Onigmo           | The C++ grammar uses `\s+{1,0}`, which Oniguruma reads as a possessive repeat; Onigmo rejects it (error -202)       |
| `scss_scanner/document`, `group_8`        | PCRE2, PCRE2 JIT | Different scanner results, for example call 12 matches pattern 12 at 10..14 where Shiki matches pattern 11 at 9..16 |

Both hosts report exactly the same cases.

## Reproducing

```bash
./scripts/prepare-oniguruma-sources.sh
./scripts/prepare-onigmo-sources.sh
pnpm install --frozen-lockfile --dir benches/shiki_js
./scripts/compare-engines.py run /tmp/ferroni-compare --cases trivial oniguruma textmate
./scripts/compare-engines.py report /tmp/ferroni-compare.md /tmp/ferroni-compare
```

Or dispatch the workflow:
`gh workflow run blacksmith-comparison.yml --ref main -f platform=both -f cases=all`.
