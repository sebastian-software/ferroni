# Selective prepared Eager record import — local diagnostic

Date: 2026-10-26. Base: `14c0f3a6e1998f4f404ee44b6c5755fd457cd97b` (2.7.2).

## Decision

The opt-in record-import prototype removes per-list program-image copying, dictionary ID remapping and repeated whole-program-image binding. Nine of ten full replay cases improve by 7.4–33.6% against the subset-assembly model; JSON is too small and variable to establish a useful gain. Search medians differ by -0.8% to +1.1%, without a material regression signal. This supports a controlled consumer A/B, not a Ferriki startup or CDN claim.

The complete-pair path remains faster when loading all scanners. Selective import can win when only some source records are needed; the prefix lane demonstrates that for TSX, HTML and Astro. The existing stable archive APIs and wire formats remain available. The new API and FREC001 metadata are experimental.

## Workload and boundary

- Apple M1 Ultra, 64 GiB, macOS 27.0.1, native arm64, release with thin LTO. Rust/compiler and binary hashes are retained in the raw provenance.
- Ten checked-in scanner traces: JSON, C, C++, SCSS, Java, Rust, TSX, HTML, Astro and PHP. Current prepared assets are regenerated by the prototype producer, rather than reusing older images.
- Six fresh processes per case/variant, twelve fresh pattern caches per process, cycling through all six variant orders and reversing case order. Tables use the median of the six process medians. Raw process medians, first-cache values and warm-search samples are retained.
- Timing includes manifest opening, payload file I/O, import and construction of every requested scanner. Trace parsing, metadata file reads and the diagnostic adapter's raw-key lookup table construction are outside timing. Files are populated in the local OS cache. Downloads, decompression, process launch, grammar parsing and rendering are excluded.
- Both selective variants use the same source-index resolution. The baseline reproduces the adapter's subsequent subset-image construction, ordered-ID remapping, binding hash and checked pair opening. It caches raw program records once in an indexed vector and pairs by ordered list, reads group data directly into its envelope, and uses shared byte owners. Host-specific JSON/index work and file-identity checks are outside this model.
- The baseline is based on [Ferriki read_pair at 512c4305](https://github.com/sebastian-software/ferriki/blob/512c43053ec125c01218eea3baeb6d1ec859f914/crates/ferriki-textmate/src/indexed_precompiled.rs#L528). Ferriki itself is not modified or measured.
- Every fresh cache replays every selected captured call and verifies match order and all capture ranges outside timing. Every requested archived group must decode successfully, with zero invalid-group fallbacks in all three variants.

## Selective prefix: first 100 captured calls

The producer still exports the full trace's archive. The consumer loads only scanners referenced by its first 100 recorded calls, preserving their order, subjects and expected captures. This is a trace prefix, not a full document or production startup measurement.

## Validation

- PASSED: full `cargo test --locked --features precompiled-eager-records-prototype`, including doctests.
- PASSED: native self-check and Rust 1.94 tests for both prepared APIs; WASI tests with self-check.
- PASSED: ordinary program loader unit/integration tests without default features.
- PASSED: `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`; upstream C comparison sources emit existing compiler warnings.
- PASSED: formatting, Rustdoc with warnings denied, cargo-deny, workflow pin checks and README figure checks. Cargo-deny reports existing unmatched license allowances.
- PASSED: documentation lint, typecheck, formatting and benchmark-claim checks. The documentation client/SSR compile completes.
- FAILED (local environment): full documentation prerender/build. The sandbox rejects the preview listener; the elevated retry cannot obtain Vite's ephemeral preview port. No documentation runtime/configuration workaround is included.

The mixed imported/compiled fallback test also exposed trait-object encoding identity differences across codegen units. Scanner compilation and program import now use one shared UTF-8 encoding reference; a regression test covers the mixed scanner.

## Reproduce and inspect

```sh
cargo build --locked --release --features precompiled-eager-records-prototype --example prepared_record_import
python3 scripts/compare-record-import.py .cache/record-import-full --memory-repetitions 3
python3 scripts/compare-record-import.py .cache/record-import-prefix --cases cpp tsx html astro --call-limit 100
```

Full and prefix timing were run first; RSS was collected afterward using the same single-child wrapper method now available with `--memory-repetitions`. The evidence archive retains raw JSON, provenance, input hashes, current runner source, source diff, environment and validation logs. Large program/group input files are omitted and can be regenerated by the commands above. Pilot measurements before the final baseline-fidelity corrections are excluded.

See `full.json`, `prefix.json` and `memory.json` for the tables' machine-readable values. `SHA256SUMS.json` covers the retained report artifacts. A production consumer A/B and broader package-layout decisions remain outside this prototype.
